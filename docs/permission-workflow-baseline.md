# 权限与审核流程基线（草案）

## 1. 权限模型

采用“用户、角色、权限、有效业务域”关系，不设置县分、网格等数据范围字段。

- 权限：`read`、`create_draft`、`update_draft`、`delete_draft`、`submit`、`review`、`apply`、`import`、`export`、`call_now`、`manage_users`、`manage_config`。
- 数据域：`business`、`network`、`callback`、`template`、`system`。

系统预置五个岗位模板，但模板只是初始配置：

| 岗位模板 | 默认权限 | 默认数据域 |
|---|---|---|
| 业务维护人 | 查询、草稿、新增/修改/作废申请、提交 | business |
| 业务稽核人 | 查询、审核、退回、应用；可选提交 | business |
| 网络维护人 | 查询、草稿、新增/修改/作废申请、提交 | network |
| 网络稽核人 | 查询、审核、退回、应用；可选提交 | network |
| 系统管理员 | 用户、角色、配置、导入导出、业务/网络审核与应用、审计查看 | system、business、network |

系统管理员拥有业务和网络的提交、审核、应用权限。其自提交、自审核必须在审核页
勾选二次确认，审核通过后仍须单独点击应用确认；两步均写入审计日志。

## 2. 审核状态机

```text
草稿 -> 待审核 -> 已通过 -> 已应用
             \-> 已退回 -> 草稿
             \-> 已驳回
草稿 ----------> 已取消
```

- 新增、修改、作废统一走变更申请。
- 退回必须指出字段和原因。
- 业务稽核人不能审核自己的提交；高风险作废和批量导入建议强制双人复核。
- 审核通过后在一个事务中应用正式数据，失败则整体回滚。
- 所有状态变更写入审计日志。

## 3. 用户与安全

从单密码升级为用户账号、密码哈希、启用/禁用和角色绑定。系统不开放自助注册，用户
账号只能由超级管理员创建、启停和赋权；新建账号在绑定角色前没有业务数据权限。
登录、登出、密码失败、导出和拨号均记录审计事件；手机号和联系人电话在列表及日志中
默认脱敏。

## 4. 电话权限

立即拨打和人工重拨是高影响操作，需要独立 `call_now` 权限、二次确认和任务来源记录。定时拨打由计划生成任务，仍由唯一的单通道 Worker 执行。通话记录只能追加事件，不能由普通维护人员删除或改写。

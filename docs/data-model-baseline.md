# 运营商运维台账数据基线（草案）

## 1. 范围与原则

本系统的主对象是“业务实例”和“网络设备”，电话回访是围绕这些对象执行的动作。
Excel 仅是导入来源，不作为数据库的最终结构。

数据分为三层：

1. 暂存层：保存原始导入行、列映射、校验结果和批次。
2. 正式层：保存当前有效的规范化主数据。
3. 历史层：保存变更前后值、操作者、审核者和时间。

所有正式数据变更都必须能追溯到一个变更申请或导入批次。

## 2. 领域模型

### 客户主体与通讯录

- `customers`：客户主体。客户名称不是业务实例的唯一键，由业务台账维护。
- `contacts`：独立通讯录，只保存负责人姓名、联系电话、职责和有效状态。
- `customer_contacts`：历史客户关联和导入追溯关系，不作为通讯录录入入口。

职责至少支持发展人、客户经理、网络维护责任人和客户。电话保存为字符串，展示时按权限脱敏。
回访任务以客户主体为归属，并在计划上明确选择通讯录负责人；实际拨号对象是该负责人，
不直接拨打客户主体。负责人职责允许填写“客户”，表示直接维护客户电话。

### 业务实例（A-M）

`business_services` 建议字段：

- `service_number`：业务号码，作为业务实例的业务唯一键。
- `customer_id`：客户主体。
- `county`、`grid`：县分和网格。
- `service_status`：服务状态字典。
- `accessed_at`、`agreement_expires_at`：入网和协议到期时间。
- `business_type`、`channel_name`。
- `source_row`、`data_quality_status`：导入来源和数据质量状态。
- `version`、`is_active`、时间戳。

业务号码目前未发现重复，但仍需在数据库建立唯一约束并在导入时给出重复预览。

### 网络设备（N-W）

`network_devices` 建议字段：

- `business_service_id`：设备所属业务实例，一条业务可拥有多台设备。
- `device_code`：非空设备编码全局唯一；同一编码不能同时属于两个业务。
- `asset_class`、`asset_value`、`device_type`、`vendor_model`。
- `location`、`recovery_status`、`recovery_reason`。
- `maintenance_contact_id`、`version`、`is_active`、时间戳。

当前业务规则是业务实例与设备的一对多关系，不建立多对多 `service_devices` 表。若同一设备编码出现在不同业务行中，视为人工录入错误并阻止该批次应用，由维护人员确认正确归属后再导入。

### 字典与扩展字段

县分、网格、业务类型、服务状态、设备属性、设备类型、回收状态和回收原因使用可停用字典项，不允许自由输入造成同义词泛滥。

后期的预留字段使用 `custom_field_definitions` 和 `custom_field_values`，仅允许管理员配置字段标签、类型、适用数据域和是否必填，不动态修改数据库列。

## 3. 变更与历史

- `change_sets`：一次人工提交或一次导入批次。
- `change_items`：新增、修改、作废操作及字段级 patch，包含 `base_version`。
- 状态：`draft`、`submitted`、`returned`、`approved`、`rejected`、`applied`、`cancelled`。
- `audit_logs`：登录、查询导出、变更、审核、拨号和管理员覆盖操作。

审核通过时检查版本；正式数据已变化则转为冲突，要求重新合并，不能覆盖他人的更新。
作废默认是软删除，历史通话和审计记录不因作废而消失。

## 4. 当前表格的数据质量结论

附件有 3,113 条有效数据行。协议到期时间、客户经理、网络维护责任人、设备属性、资产价格和放置地点等列目前基本为空；“未回收原因”同时包含回收状态描述。这些字段应在导入预览中标为缺项或语义异常，而不是直接判定为合法空值。

Q 列有 1,457 个非空单元格，其中 9 个单元格使用 `、` 或换行填写多个设备 ID。按分隔符拆分后共有 1,467 个设备 ID，其中 107 个 ID 各出现在两个不同业务行中。前者应拆成同一业务下的多台设备，后者是唯一键冲突，必须修正后才能进入正式库。

## 5. 规范化表与 Excel 的交换格式

规范化数据库不要求用户直接理解多张表。人机交换唯一采用一个中文工作表
`业务设备台账`，保留接近 A-W 的扁平列；不导出 `dictionary_snapshot` 或英文规范化
工作表。每行表示一个业务与一个设备的关联，同一业务可以有多行设备。

末尾的 `业务记录ID`、`业务版本`、`设备记录ID`、`设备版本` 是系统校验字段，用户
不应修改。它们用于导出后本地修改再回传；系统同时用业务号码和设备编码校验稳定键，
版本不一致时报告冲突，不会覆盖导出后发生的更新。导出文件另含中文 `填写说明`
工作表，并在固定枚举字段提供下拉校验。

原始 A-W 台账导入时，A-M 映射到业务实例，N-W 映射到设备。Q 列按 `、`、中文/英文逗号、分号和换行拆分，每个设备 ID 生成一条属于该业务的设备记录，并继承该行的其他设备字段。设备 ID 跨业务重复、联系人无法匹配或一行包含冲突值时进入异常清单。

批量修改不直接执行 SQL：用户选择导出文件或页面筛选结果后，系统生成业务、网络两个
域的 `change_set`，分别审核并通过后在事务中应用；只有两域申请全部应用，导入批次才
标记为已应用。

# 台账管理 Web 交互基线（草案）

## 1. 页面结构

侧边栏分为：工作台、客户与台账（业务台账、网络设备）、数据管理（审核中心、
缺项工作台、导入导出、维系与回收）、回访与通话（通讯录、扫描通知、话术管理、
通话记录）、系统管理（系统监控、备份与灾备、用户管理、角色权限）。
首页显示待审核、缺项数量、到期业务、当前拨号状态和最近异常。

## 2. 台账列表

- 顶部搜索支持业务号码和客户名称模糊查询。
- 筛选支持县分、网格、服务状态、业务类型、维护责任人、缺项和变更状态。
- 表格默认固定业务号码、客户名称、县分、网格；业务字段与设备字段用分组列切换，不默认挤出 23 列。
- 服务端分页、列显示选择、排序和可保存筛选视图。
- 手机号按权限显示完整值，否则只显示首尾部分。

## 3. 详情与编辑

点击行打开右侧详情抽屉，分为业务信息、所属设备、联系人、审核历史、通话记录五个页签。业务和网络维护人员只能编辑自己有权限的分组。

编辑状态显示必填提示、格式错误、字典选择和缺项提醒；保存为草稿后再提交审核。提交前显示字段级变更摘要，避免用户不知道将提交什么。

设备使用可增删的明细子表，一台设备一行，不要求用户在一个输入框中用分隔符填写多个设备 ID。设备 ID 重复时立即提示现有归属业务。作废操作显示所属设备、计划和通话影响，并要求确认理由。

## 4. 审核中心

审核中心按待审核、已退回、已驳回、已应用筛选，显示提交人、域、范围、批次、等待时间和缺项数量。审核详情采用“当前正式值 / 提交值”并排对比，支持逐字段接受或退回，退回必须填写原因。

低风险、同类型、同批次的变更可批量审核；含唯一键冲突、作废、联系人电话或大量缺项的批次必须逐条处理。

## 5. 导入、缺项与导出

导入向导依次完成文件上传、表头映射、类型校验、重复检查、缺项检查、差异预览和提交审核。原始行与错误信息保留在暂存区，不能直接覆盖正式表。

缺项工作台按字段和责任人聚合，可直接进入暂存行详情补齐并重新校验。导出只由系统
管理员执行，采用扁平台账并记录导出条件与批次；业务和网络变更仍分别进入审核链路。

## 6. 通知与回访入口

通讯录（/contacts）是独立的人名+电话绑定目录，与客户主体无关；客户主体由台账
导入审核链路自动创建。扫描通知（/scan-schedules）配置每日/每周定时扫描（到期
维系、退网设备回收、审核卡单提醒），不再按客户手动建回访计划。

维系与回收工作台（/due-work）列出到期窗口业务与退网未回收设备，提供续签、
退网、回收完成三类变更申请入口，提交后进入审核中心；页面同时展示今日是否已
通知及最近申请状态。业务或设备详情页保留“立即拨打一次”，拨号前显示目标
联系人、号码、话术版本和预计执行时间。通话页突出未接通及有效时长不足 10 秒
的记录，并保留串口事件时间线。

## 7. 导入暂存更正

导入报告只展示校验结果和暂存行，不在页面展开表头映射明细。表头识别规则、括号说明
兼容和技术校验列说明统一维护在 `docs/import-guide.md`。点击“更正”后，字段按
`business`（业务信息）和 `device`（设备信息）分组；操作者可从字段选择器定位需要修改
的字段。字典和联系人字段使用可输入的自动补全控件，允许录入尚未纳入候选列表的自定义值，提交
后由服务层按现有校验规则重新校验。系统校验字段只读展示，不允许人工覆盖。
